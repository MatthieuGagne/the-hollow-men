01 Overview

The Hollow Men is a 2D turn-based JRPG set in NOX, a perpetually rain-soaked cyberpunk city. Protagonist Reid investigates a missing person case, descending into Lovecraftian horror and corporate bureaucratic magic. The game is built entirely in Godot 4.6 using GDScript for runtime logic and C# only for editor tooling (the YATI tilemap importer and YarnSpinner importer).

The game runs at 320×180 (stretched to 1280×720). The Mobile renderer (GL Compatibility) is used for broad device support. All sprite art is pixel art aligned to this grid.

High-level structure

The game is divided into two primary gameplay loops, each with its own scene:

LoopSceneDescription
World explorationRoomPOC.tscnGrid-based movement, NPC dialogue, interactable objects, battle encounters
BattleBattleScene.tscnTurn-based ATB combat with party of 4 vs enemies

02 Key Patterns

Understanding these four patterns explains most of the code you'll encounter.

Signal-driven UI

UI nodes connect to autoload signals and react to them — they never poll or call into game logic directly. BattleScene emits combatant_updated; HUD listens and refreshes. This keeps UI and game logic fully decoupled.

battle_scene.combatant_updated.connect(_on_combatant_updated)

Grid-based world

The world is a 16×16px tile grid. Player movement is discrete (one tile at a time). The CellRegistry autoload tracks which cells are blocked or interactable, so any node can register itself without knowing about Player.

CellRegistry.register_blocking(cell, self)

ATB combat

Combatants have an ATB gauge (0–100) that fills over time. When full, it's that combatant's turn. Player-controlled turns pause the timer and show the ActionMenu. This gives real-time feel with turn-based depth.

combatant.tick_atb(delta) # fills each frame

Resource-based data

Characters and abilities are Resource subclasses (Combatant, Ability), saved as .tres files. This separates data from behavior and allows easy serialization without custom parsers.

var reid = load("res://data/combatants/reid.tres")

Static typing everywhere

All variables and function signatures use explicit GDScript types. This catches errors at parse time and makes the codebase easier to navigate without an IDE. Always type-hint when adding new code.

var party: Array[Combatant] = []

TDD with GUT

Every module has a corresponding tests/test_*.gd file. The rule is: write the failing test first, then the implementation. Tests run headlessly via godot --headless -s addons/gut/gut_cmdln.gd.

func test_take_damage_reduces_hp(): ...

05 Autoloads

Autoloads are global singletons accessible from any script without importing. They are registered in Project → Project Settings → Autoload. Treat them like services — lean, with well-defined responsibilities.

SceneManager

autoload
scripts/autoload/scene_manager.gd
Handles all scene transitions with a smooth black fade overlay. Never call get_tree().change_scene_to_file() directly — always go through SceneManager.change_scene(path) to preserve the fade effect and let AudioManager know a transition is happening.
Signals
pre_scene_change — emitted just before the scene swap; AudioManager connects here to fade music
Methods
change_scene(path: String) — fades to black (0.3s), swaps scene, fades back in
Implementation notes

Uses a ColorRect overlay on CanvasLayer 100 (above everything). Fade is a 0.3-second tween on the alpha. The overlay is added directly to the SceneManager node, not the scene, so it persists through transitions.

CellRegistry

autoload
scripts/autoload/cell_registry.gd
The spatial index for the world grid. Objects register themselves here on _ready() and unregister on _exit_tree(). The Player queries this each step to know whether movement is blocked and whether there's something to interact with. This pattern means Player never needs direct references to individual world objects.
Internal data
_blocking Dictionary[Vector2i, Node] — cells that block movement
_interactables Dictionary[Vector2i, Node] — cells with interact handlers
Methods
register_blocking(cell: Vector2i, node: Node)
unregister_blocking(cell: Vector2i)
is_blocked(cell: Vector2i) → bool
register_interactable(cell: Vector2i, node: Node)
unregister_interactable(cell: Vector2i)
get_interactable(cell: Vector2i) → Node
clear() — used in tests to reset state

AudioManager

autoload
scripts/autoload/audio_manager.gd
Manages background music with smooth 1.5-second cross-fades. Automatically stops music before scene transitions by connecting to SceneManager.pre_scene_change. Call play_music from scene _ready() functions to set the track for that scene.
Methods
play_music(path: String) — fades in the given audio file
stop_music() — fades out current track

BattleParams

autoload
scripts/autoload/battle_params.gd
A simple data bag for passing state from the world to the battle scene during the scene transition. Because Godot scene changes destroy the calling scene, parameters cannot be passed via function arguments — they're written here before SceneManager.change_scene() and read in BattleScene._ready().
Properties
background_id String — which battle background sprite to display (e.g. "alley", "office")

06 Battle System

The battle system is a classic Active Time Battle (ATB) system. Each combatant has a gauge that fills over time; when full it's their turn. The state machine in BattleScene drives the loop.

Combatant

resource
scripts/battle/combatant.gd — extends Resource
The single source of truth for a character's stats and runtime state. Saved as .tres files in data/combatants/. Exported properties are the baseline data; runtime properties (current HP, ATB fill) are populated when battle starts.
Enum
SigilType.NONE
SigilType.BUREAU — limit break capped at 80% (corporate compliance restriction)
SigilType.JAILBROKEN — no cap
Exported stats
character_nameString
is_player_controlledbool
abilityAbility
max_hp, max_ppint
str_stat, def_stat, psy_stat, res_stat, spd_statint
sigil_typeSigilType
Runtime state
current_hp, current_ppint
atbfloat — 0 to ATB_MAX (100.0)
limit_gaugefloat — 0 to LIMIT_MAX (100.0), capped at 80 for Bureau sigil
Key methods
tick_atb(delta) — fills ATB by spd_stat × ATB_FILL_RATE × delta
take_damage(amount) / heal(amount) / spend_pp(cost)
hp_ratio() / pp_ratio() / atb_ratio() / limit_ratio() → float — for UI bars
calculate_damage(attacker, defender) → int — static, STR vs DEF formula

Ability

resource
scripts/battle/ability.gd — extends Resource
Simple data container for an ability. Each Combatant can have one Ability assigned. The ability name is used to look up behavior in BattleScene.execute_action().
Exported properties
ability_nameString
pp_costint
targets_partybool — true for ally-targeting abilities (triggers target selection mode)

BattleScene

scene
scenes/battle/BattleScene.tscn · scripts/battle/battle_scene.gd — extends Node2D
The main battle controller. Owns the ATB state machine, drives combatant turns, processes actions, and emits signals for the HUD to react to. The scene tree looks like:
BattleScene (Node2D) ← battle_scene.gd
├── Background (Sprite2D) — dynamic, set from BattleParams.background_id
├── EnemyContainer (Node2D) — enemy sprites placed here
├── PartyContainer (Node2D) — party sprites placed here
└── UI (CanvasLayer)
    ├── HUD (Control) ← hud.gd
    │   ├── EnemyWindow, PartyWindow, ActionMenu
    ├── FlashOverlay (ColorRect) — damage flash effect
    └── DefeatMenu (Control) ← defeat_menu.gd
State machine
TICKING — ATB gauges filling; no input accepted
AWAITING_INPUT — player's turn; ActionMenu is visible
ANIMATING — action in progress; no input accepted
SELECTING_ALLY — player is picking a party target for an ally ability
PAUSED — pause menu open
ENDED — battle finished (victory or defeat); transition pending
Signals
battle_ended(victory: bool)
combatant_updated(combatant: Combatant) — HUD redraws on this
player_turn_started(combatant: Combatant)
player_turn_ended()
party_target_changed(combatant: Combatant)
pause_toggled(paused: bool)
Key methods
execute_action(action_name: String) — called by ActionMenu; dispatches Attack or Ability logic
confirm_party_target(target: Combatant) — called after ally selection
skip_turn() — enables skip cooldown on active combatant

07 World System

The world is a tile grid where the player explores, reads objects, and talks to NPCs. Movement is turn-by-turn (one tile per keypress). Blocking and interaction are handled through the CellRegistry rather than physics colliders.

RoomPOC

scene
scenes/world/RoomPOC.tscn · scripts/world/room_poc.gd — extends Node2D
The current main scene (the game's entry point). A proof-of-concept room that will eventually be replaced by a proper room system. Sets the battle background for any encounters spawned in this room and starts background music.
RoomPOC (Node2D) ← room_poc.gd
├── room_poc (TileMapLayer) — imported from room_poc.tmx via YATI
│   └── World (Node2D) — YATI object layer container
│       └── Interactions (Node2D) — interactive object instances
├── Player (CharacterBody2D) ← player.gd
├── UILayer (CanvasLayer 10)
│   ├── DialogueBox ← dialogue_box.gd
│   ├── DialogueRunner — YarnSpinner runtime
│   └── YarnDialogueBridge ← yarn_dialogue_bridge.gd
├── FlickeringLight (PointLight2D) ← flickering_light.gd
└── CanvasModulate (Color: 0.08, 0.08, 0.12) — deep blue-black ambient
The tilemap is imported from a Tiled .tmx file via the YATI plugin. Wall tiles have class="wall" in the .tsx tileset, stored as tile metadata. Player reads this to check movement blocking — not the CellRegistry.

Player

class
scripts/world/player.gd — extends CharacterBody2D
Handles grid-based movement and world interaction. Movement is discrete: each keypress moves exactly one tile after checking for walls and registry-blocked cells. Interaction looks up the facing cell in CellRegistry and calls interact() on whatever is there. Input is blocked during dialogue.
Constants
TILE_SIZE= 16 — pixels per tile
MOVE_DURATION= 0.1 — seconds to tween between tiles
Key methods
_try_move(action) — checks wall tile + CellRegistry before tweening
_try_interact() — looks up facing cell in CellRegistry, calls node.interact()
_is_wall(world_pos) → bool — reads TileData metadata for "wall" class
get_facing_cell() → Vector2i
snap_to_grid(pos) → Vector2 — snaps to tile center (uses floorf + half-tile offset)

WorldObject

class
scenes/world/WorldObject.tscn · scripts/world/world_object.gd — extends Node2D
Base class for any object that occupies tiles in the world. On _ready() it calculates which cells it spans (based on tile_cols × tile_rows) and registers them as blocking in CellRegistry. Automatically unregisters on _exit_tree(). NPC extends this.
Exported properties
object_nameString
sprite_textureTexture2D
blocks_movementbool
tile_cols, tile_rowsint — size in tiles

NPC

class
scenes/world/NPC.tscn · scripts/world/npc.gd — extends WorldObject
An interactable character. Extends WorldObject (so it blocks movement and registers cells). When the player interacts, it triggers a YarnSpinner dialogue by node ID.
Exported properties
yarn_node_idString — YarnSpinner node to run (e.g. "Iris.Intro")
Methods
interact(_dialogue_box, yarn_bridge) — calls yarn_bridge.start_dialogue(yarn_node_id)

ExamineObject

class
scenes/world/ExamineObject.tscn · scripts/world/examine_object.gd — extends Node2D
A static world prop that shows text when examined. Does not extend WorldObject (it has no sprite or blocking — it's usually placed on top of a decorative tile). Registers a single cell as interactable in CellRegistry.
Exported properties
examine_textString
Methods
interact(dialogue_box, _yarn_bridge) — calls dialogue_box.show_text(examine_text)

BattleEncounter

class
scenes/world/BattleEncounter.tscn · scripts/world/battle_encounter.gd — extends Area2D
An invisible trigger zone in the world. When Player enters it, it sets BattleParams.background_id and calls SceneManager.change_scene() to the battle scene. The red ColorRect child is a visual aid in the editor only.
Exported properties
battle_background_overrideString — overrides the room default if set

World

class
scripts/world/world.gd — extends Node2D
Manages the room's encounter rate mode. Player calls on_player_stepped() on every tile movement; World rolls for a random encounter based on the current mode.
Enum — Mode
INVESTIGATION — 0% encounter rate (safe exploration)
HOT_ZONE — 2% per step
RUINS — 4% per step

FlickeringLight

class
scripts/world/flickering_light.gd — extends PointLight2D
Animates light energy between min and max values on randomized intervals to simulate a fluorescent flicker. Uses a recursive tween loop — when one tween finishes it starts the next.
Exported properties
min_energy, max_energyfloat
flicker_min_duration, flicker_max_durationfloat — random range per flicker

08 UI System

UI nodes connect to game signals — they never call into gameplay code directly. All UI scenes live in scenes/ui/.

DialogueBox

scene
scenes/ui/DialogueBox.tscn · scripts/ui/dialogue_box.gd — extends Control
Handles both plain text display (examine objects) and full YarnSpinner dialogue (speaker name, typewriter text reveal, choice lists). Positioned at the bottom of the screen at full width.
DialogueBox (Panel)
├── SpeakerLabel — character name
├── Label — main text (autowrap, typewriter effect)
└── ChoiceList (VBoxContainer) — shown during choices
States

Signals

Methods

show_line(speaker, text) — speaker + typewriter text (YarnSpinner)

HUD

class
scripts/ui/hud.gd — extends Control
Displays the battle status: enemy names in a top panel, party HP/PP/ATB bars in a bottom panel. Panels are generated dynamically at runtime from the combatant array. Connects to BattleScene signals to refresh without polling.
Setup

Color conventions

HP bar: green → red as HP falls. PP bar: purple. ATB bar: white. Limit break bar: grey (inactive), gold (active). Bureau sigil combatants have a dimmer gold cap at 80%.

09 Tests

If you add a new class_name script, run make import first — GUT won't find the class until the global class registry is rebuilt.
